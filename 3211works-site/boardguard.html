BoardGuard for Jira

See board risk and dependency impact before a change becomes an incident.

BoardGuard gives Jira administrators a read-only view of board health signals, Saved Filter dependencies, repeated configuration issues, and potential blast radius.

Read-only workflowAtlassian ForgeNo external backend in current release

What BoardGuard checks

Board configurationFlags configuration signals such as invalid Kanban sub-filter JQL, Quick Filter JQL issues, and board filters that are not ordered by Rank where that can affect drag-and-drop behavior.
Saved Filter dependenciesGroups boards by their underlying Saved Filter so an administrator can see when one filter is shared by multiple boards.
Change impactShows the boards that depend on the same Saved Filter, together with owner, sharing scope, current JQL, and an impact indicator.
Repeated signalsGroups the same issue across multiple boards so duplicated symptoms are easier to distinguish from a shared root cause.

Designed for administrators

BoardGuard is intentionally focused. It is not a general Jira management platform and it does not try to automate every administrative action. Its job is to make configuration risk easier to see before an administrator edits, removes, or hands over a shared object.

Read-only by design. The current BoardGuard release is designed to inspect Jira configuration and present findings without changing Jira settings on the administrator's behalf.

Data path

BoardGuard is built on Atlassian Forge. In the current release, BoardGuard does not use a separate application backend operated by 3211 Works and does not intentionally send Jira content to 3211 Works-operated servers. Jira API access is performed in the context of the signed-in Atlassian user and remains subject to Jira permissions.

For more detail, see our Privacy Policy and Security page.
