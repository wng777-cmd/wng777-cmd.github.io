Security

Reduce the data path. Keep the product focused.

BoardGuard is designed around a small attack surface, a read-only workflow, and Atlassian-hosted execution.

BoardGuard architecture

Atlassian ForgeThe current release is built on Forge and has passed Forge Runs on Atlassian eligibility checks in development.
No external application backendThe current release does not use a 3211 Works-operated remote application server for Jira data processing.
Read-only product intentBoardGuard is designed to inspect and report on Jira configuration rather than modify Jira settings automatically.
Permission-awareJira API access remains subject to the permissions of the signed-in Atlassian user.

Development and release controls

BoardGuard release checks include dependency vulnerability scanning, Forge linting and deployment validation, Runs on Atlassian eligibility checking, and source-level guards intended to prevent Jira write operations from being introduced unnoticed.

These controls reduce risk but do not eliminate every possible vulnerability. We review credible reports and update the product when a security issue is confirmed.

Report a vulnerability

Email security@3211works.com with a clear description of the issue, affected product, reproduction steps, and expected security impact.

Please do not include live credentials. Do not send passwords, API tokens, private keys, session cookies, or unnecessary customer data in an initial report.

Coordinated handling

We ask security researchers to avoid privacy violations, destructive testing, service disruption, or accessing data that does not belong to them. If a report is valid, we will work to understand scope and remediation before public disclosure.
